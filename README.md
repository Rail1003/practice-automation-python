# Полуфинал — Автоматизация тестирования (Python)

UI-автотесты сайта [Practice Automation](https://practice-automation.com/) на
Python 3.12+, Selenium и Pytest. Архитектура — Page Object Model. Основная целевая
платформа — Windows, браузеры Chrome и Firefox. Отчёт — Allure.

**36 сценариев на браузер, 72 запуска при `--browser=all`.** Для каждой из трёх
обязательных страниц выполнено требуемое количество позитивных и негативных
сценариев. Обязательное заполнение Message реализовано отдельным тестом Form Fields.

| Страница | Позитивные | Негативные | Всего |
| --- | ---: | ---: | ---: |
| Calendars | 8 | 4 | 12 |
| Modals | 8 | 4 | 12 |
| Ads | 7 | 4 | 11 |
| Form Fields — дополнительный обязательный пункт | 1 | 0 | 1 |
| **Итого** | **24** | **12** | **36** |

## Статус проверки

Проверены синтаксис, Ruff, сборка всех 72 тестов и ключевые сценарии на живом сайте
через доступный облачный Chrome. **Полный прогон Selenium на Windows пока не
подтверждён:** среда подготовки — изолированный Linux-контейнер, в котором Chrome
и Firefox не смогли создать WebDriver-сессии. Это ограничение среды, а не результат
проверки функциональности сайта. Исходный диагностический прогон и его Allure-отчёт
находятся в `docs/verification/blocked-run/`; его два теста имеют статус Broken.
Подробности и границы проверки: [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Быстрый запуск на Windows

Установите Python 3.12 или новее и актуальные Chrome / Firefox. Для генерации
Allure-отчёта дополнительно нужны Java 17+ и Node.js LTS с npm / npx.
Java и Node.js не нужны для самого запуска Pytest и сохранения `allure-results`.
Все команды ниже выполняются из папки проекта в PowerShell.

### Установка зависимостей

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Активация виртуального окружения не требуется. Если команда `py` отсутствует,
используйте `python` вместо `py -3` и проверьте `python --version`.
Версии трёх основных зависимостей зафиксированы в `requirements.txt`;
`requirements-dev.txt` дополнительно устанавливает Ruff.

### Запуск всех тестов и создание отчёта

```powershell
$runDir = "artifacts\run-$(Get-Date -Format 'yyyyMMdd-HHmmss-fff')"
.\.venv\Scripts\python.exe -m pytest --browser=all --headless --alluredir="$runDir\allure-results" --junitxml="$runDir\junit.xml"
npx.cmd --yes allure-commandline@2.46.1 generate "$runDir\allure-results" --output "$runDir\allure-report"
npx.cmd --yes allure-commandline@2.46.1 open "$runDir\allure-report"
```

Каждый запуск получает отдельную папку, поэтому результаты разных прогонов не
смешиваются. Уберите `--headless`, чтобы видеть браузер. Для единственного браузера
замените `--browser=all` на `--browser=chrome` или `--browser=firefox`.
Драйвер подбирается встроенным Selenium Manager. При первом запуске нужен доступ
к серверам загрузки браузерных драйверов. Внешние блокировщики рекламы не используются:
каждый тест запускает новый чистый профиль браузера без пользовательских расширений.

### Вспомогательные PowerShell-скрипты

Если запуск `.ps1` разрешён существующей политикой вашей системы:

```powershell
powershell -NoProfile -File scripts\setup.ps1
powershell -NoProfile -File scripts\run.ps1 -Browser all -Headless
```

`run.ps1` печатает фактический путь к результатам и команду создания отчёта.
Например, для напечатанного пути:

```powershell
powershell -NoProfile -File scripts\report.ps1 -Results "artifacts\run-20261001-180000-000-all\allure-results" -Open
```

Скрипт запуска сохраняет exit code Pytest. Скрипт отчёта проверяет наличие Java,
npx и реальных JSON-результатов. Если выполнение `.ps1` запрещено, используйте
прямые команды выше; менять политику PowerShell для проекта не требуется.

### Выбор страниц, типов сценариев и отдельного теста

```powershell
.\.venv\Scripts\python.exe -m pytest --browser=chrome --headless -m calendars
.\.venv\Scripts\python.exe -m pytest --browser=firefox --headless -m "modals and negative"
.\.venv\Scripts\python.exe -m pytest --browser=all --headless -m form_fields
.\.venv\Scripts\python.exe -m pytest --browser=chrome --headless -k leap_day
.\.venv\Scripts\python.exe -m pytest --collect-only -q --browser=all
.\.venv\Scripts\python.exe -m ruff check .
```

Эти короткие команды используют `allure-results/` по умолчанию. Для нового полного
отчёта используйте уникальную папку, как в примере полного запуска.
Параметры: `--timeout=15` для явных ожиданий, `--page-load-timeout=60`,
`--base-url=https://practice-automation.com`. Нулевые и отрицательные таймауты
отклоняются до запуска тестов.

Если автоматическая загрузка драйверов недоступна, задайте собственные совместимые
драйверы и при необходимости пути к нестандартным браузерам:

```powershell
$env:CHROMEDRIVER_PATH = "C:\WebDrivers\chromedriver.exe"
$env:GECKODRIVER_PATH = "C:\WebDrivers\geckodriver.exe"
# Только если браузеры установлены в нестандартное место:
$env:CHROME_BINARY = "C:\Browsers\Chrome\chrome.exe"
$env:FIREFOX_BINARY = "C:\Browsers\Firefox\firefox.exe"
```

## Структура и технические решения

| Путь | Назначение |
| --- | --- |
| `automation/pages/base_page.py` | Открытие страниц, явные ожидания, ввод, подтверждение отправки |
| `automation/pages/calendar_page.py` | Календарь, пагинация, валидация даты |
| `automation/pages/modals_page.py` | Простое окно, форма, открытие и закрытие |
| `automation/pages/ads_page.py` | Отложенная реклама и её жизненный цикл |
| `automation/pages/form_fields_page.py` | Получение Automation Tools и заполнение Message |
| `tests/test_*.py` | Сценарии, тестовые данные и проверки ожидаемого поведения |
| `conftest.py` | Настройки, Chrome / Firefox, фикстуры и вложения при ошибках |
| `scripts/` | Установка, запуск и отчёт для Windows |
| `.github/workflows/ui-tests.yml` | Ручной запуск GitHub Actions на Windows в обоих браузерах |
| `docs/VERIFICATION.md` | Фактически выполненные проверки и ограничения |

Локаторы и действия находятся в Page Object, бизнес-проверки — в тестах. Нет
`time.sleep`, неявных ожиданий, автоматических повторов тестов, `skip` или `xfail`.
Обнаруженное несовпадение ожиданий с сайтом приводит к явному падению.
Ожидания исчезновения учитывают анимацию окон. Каждый сценарий получает новый
WebDriver и чистый профиль; состояние, cookies и отправленные формы не переносятся
в следующий тест. Тестовые контакты синтетические: `Automation Test`,
`ui-test@example.com`; личные данные пользователя не используются.

В календаре соседние дни предыдущего / следующего месяца исключаются из локатора
выбора дня. Сегодняшняя дата берётся по часовому поясу браузера. Остальные данные
фиксированы, чтобы переходы через границы месяца и года воспроизводились независимо
от даты запуска. Форма сайта использует `novalidate` и собственную валидацию Jetpack:
проверяются её сообщения и `aria-invalid`, а не текст стандартной подсказки браузера.

## Тестовые сценарии

Общие предусловия: сайт доступен, чистый профиль Chrome / Firefox, открыта указанная
страница, блокировщик рекламы отсутствует. Ожидание UI — до `--timeout` секунд.
ID совпадают с префиксами названий в Allure и позволяют найти реализацию поиском
по исходникам. Строки таблиц — самостоятельные сценарии; четыре негативных случая
календаря реализованы параметризацией и дают четыре отдельных результата.

Негативные проверки окон проверяют запрещённые действия и нежелательные повторные
показы: у Ads нет полей ввода, поэтому проверки некорректных данных к ней неприменимы.
Проверки опираются на конфигурацию сайта, наблюдаемую 01.10.2026: у простой модалки
и Ads закрытие по Escape отключено, у модальной формы включено; закрытие по фону
отключено. Автопоказ Ads настроен на 4500 мс, хотя текст страницы говорит примерно
о пяти секундах. Поэтому проверяется автоматическое появление с явным ожиданием,
а не точность таймера до миллисекунд.

## Allure

У каждого теста — читаемый заголовок с ID и группировка Epic / Feature; действия
Page Object оформлены шагами. Отчёт содержит браузер, capabilities и окружение.
При падении на этапе setup или выполнения теста прикладываются PNG-скриншот,
HTML страницы, URL и исходная ошибка. Сбой сбора вложения не заменяет исходную
ошибку. Если WebDriver не создал сессию или уже потерял её, получить скриншот
физически невозможно: вместо него добавляется отдельное объяснение.

Сохранённый диагностический отчёт можно открыть, например:

```powershell
npx.cmd --yes allure-commandline@2.46.1 open docs\verification\blocked-run\allure-report
```

Allure-отчёт открывайте через `allure open`, а не двойным щелчком по `index.html`:
браузеру нужен локальный HTTP-сервер для загрузки JSON отчёта.

## Размещение для проверки

ZIP подготовлен для передачи исходников. Согласно PDF, итоговую работу нужно
разместить в GitHub / Bitbucket / GitVerse и отправить ссылку через личный кабинет.
Создайте пустой репозиторий без автоматически создаваемого README и загрузите
содержимое папки проекта; виртуальное окружение и локальные результаты не нужны.

При использовании Git выполните из папки проекта, подставив свой адрес:

```powershell
git init
git add .
git commit -m "Add Selenium UI tests with Pytest, Page Objects and Allure"
git branch -M main
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

В GitHub вкладка Actions → UI tests on Windows → Run workflow запускает матрицу
Chrome / Firefox. Результаты, JUnit и готовый Allure-отчёт доступны в артефактах
каждого задания, включая случаи падения тестов. Workflow запускается вручную,
чтобы не создавать лишние обращения к публичному учебному сайту при каждом коммите.
